## Что нового

### Поддержка ядра Mihomo с живым выбором серверов

Теперь рядом с Xray можно использовать второе прокси-ядро — Mihomo (Clash.Meta), с безопасным переключением между ядрами и выбором сервера прямо из приложения, на лету.

**Как это работает:**
- В **Настройки → «Ядро прокси»** можно установить Mihomo, собрать для него конфиг из текущих серверов Xray и переключиться — с проверкой конфига и автоматическим откатом, если что-то пошло не так.
- На вкладке **«Серверы»** в режиме Mihomo появляется список узлов с реальными задержками; тап по серверу мгновенно переключает выход (через REST API ядра), а `AUTO` выбирает самый быстрый.
- **Дашборд** и **«Роутинг»** показывают, какое ядро сейчас активно.

**Под капотом:**
- Конфиг Mihomo генерируется из аутбаундов и правил Xray: группы `PROXY` (ручной выбор) и `AUTO` (по минимальной задержке).
- Приложение общается с external-controller Mihomo через SSH + curl на роутере (контроллер слушает только loopback).
- Изменения роутинга в режиме Mihomo автоматически пересобирают конфиг и применяются без полного перезапуска.

### Важный фикс транспорта на Keenetic

Найден и устранён баг, из-за которого в режиме Mihomo часть трафика (например, Claude или приложение YouTube на телевизоре) зависала, хотя интернет в целом работал, а на телефоне всё открывалось.

**Причина:** xkeen для Mihomo направлял TCP через TPROXY, у которого на ядре Keenetic ломалась доставка данных установленного соединения — рукопожатие проходило, но TLS ClientHello не доходил до ядра, и соединения зависали (накапливались сотни «мёртвых» соединений).

**Решение:** генератор теперь добавляет в конфиг `redir-port` (TCP через REDIRECT/NAT) рядом с `tproxy-port` (UDP через TPROXY) — xkeen настраивает перехват ровно так же, как в рабочем режиме Xray. Причина найдена через packet-capture и сравнение правил iptables на реальном роутере.

### Прочее
